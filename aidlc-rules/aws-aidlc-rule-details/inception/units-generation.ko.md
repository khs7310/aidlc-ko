# 단위 생성 - 세부 단계

## 개요
이 단계에서는 시스템을 두 개의 통합된 부분을 통해 관리 가능한 작업 단위로 분해합니다.
- **1부 - 계획**: 질문으로 분해 계획 작성, 답변 수집, 모호성 분석, 승인 받기
- **파트 2 - 생성**: 승인된 계획을 실행하여 유닛 아티팩트 생성

**정의**: 작업 단위는 개발 목적으로 스토리를 논리적으로 그룹화한 것입니다. 마이크로서비스의 경우 각 단위는 독립적으로 배포 가능한 서비스가 됩니다. 모놀리스의 경우 단일 유닛은 논리 모듈이 포함된 전체 애플리케이션을 나타냅니다.

**용어**: 독립적으로 배포 가능한 구성 요소에는 "서비스"를 사용하고 서비스 내의 논리적 그룹화에는 "모듈"을 사용하며 계획 컨텍스트에는 "작업 단위"를 사용합니다.

## 전제조건
- 작업공간 감지가 완료되어야 합니다.
- 요구사항 분석 권장(기능 범위 제공)
- 사용자 스토리 권장(스토리가 단위에 매핑됨)
- 애플리케이션 설계 단계 필수(구성 요소, 방법 및 서비스 결정)
- 실행 계획에는 설계 단계가 실행되어야 함을 나타내야 합니다.

# 1부: 계획

## 1단계: 작업 단위 계획 생성
- 시스템을 작업 단위로 분해하기 위한 확인란[]을 사용하여 계획을 생성합니다.
- 시스템을 관리 가능한 개발 단위로 나누는 데 중점을 둡니다.
- 각 단계와 하위 단계에는 확인란 []이 있어야 합니다.

## 2단계: 계획에 필수 단위 아티팩트 포함
**항상** 단위 계획에 다음과 같은 필수 항목을 포함하세요.
- [ ] 단위 정의 및 책임이 있는 `aidlc-docs/inception/application-design/unit-of-work.md` 생성
- [ ] 종속성 매트릭스를 사용하여 `aidlc-docs/inception/application-design/unit-of-work-dependency.md` 생성
- [ ] 단위에 대한 `aidlc-docs/inception/application-design/unit-of-work-story-map.md` 매핑 스토리 생성
- [ ] **그린필드에만 해당**: `unit-of-work.md`의 문서 코드 구성 전략(구조 패턴은 code- Generation.md 참조)
- [ ] 단위 경계 및 종속성 검증
- [ ] 모든 스토리가 단위에 할당되었는지 확인

## 3단계: 상황에 맞는 질문 생성
**지침**: 요구 사항, 스토리 및 애플리케이션 설계를 철저하게 분석하여 설명을 통해 단위 분해 품질을 향상시킬 수 있는 모든 영역을 식별합니다. 분해 문제를 포괄적으로 다룰 수 있도록 적극적으로 질문하십시오.

**중요**: 단위 경계나 분해 품질에 영향을 미칠 수 있는 모호함이나 누락된 세부 사항이 있는 경우 기본적으로 질문을 합니다. 시스템이 어떻게 분해되어야 하는지에 대해 잘못된 가정을 하는 것보다 너무 많은 질문을 하는 것이 더 좋습니다.

**필수**: 각 카테고리에 대해 타겟 질문을 하여 다음 카테고리를 모두 평가하세요. 각 범주에 대해 요구 사항, 스토리 및 애플리케이션 설계의 증거를 기반으로 적용 가능성을 결정합니다. 명시적인 정당성 없이 범주를 건너뛰지 마십시오.

- [답변]을 사용한 질문 삽입: 태그 형식
- 모호함, 누락된 정보 또는 설명이 필요한 영역에 중점을 둡니다.
- 사용자 입력이 분해 결정을 향상시킬 수 있는 모든 곳에 질문을 생성합니다.
- **의심스러운 경우 질문하세요** - 과신은 단위 경계를 열악하게 만듭니다.

**평가할 질문 카테고리**(모든 카테고리 고려):
- **스토리 그룹화** - 그룹화 전략, 스토리 유사성, 논리적 클러스터링 접근 방식에 대해 질문합니다.
- **종속성** - 통합 접근 방식, 공유 리소스, 단위 간 통신 패턴에 대해 질문하세요.
- **팀 조정** - 팀 구조, 소유권 경계, 공동작업 모델에 대해 물어보세요.
- **기술적 고려 사항** - 단위마다 다를 수 있는 확장성/배포 요구 사항에 대해 문의하세요.
- **비즈니스 도메인** - 도메인 경계, 제한된 컨텍스트, 비즈니스 기능 조정에 대해 질문합니다.
- **코드 구성(그린필드 다중 장치만 해당)** - 배포 모델 및 디렉터리 구조 기본 설정에 대해 문의

## 4단계: UOW 계획 저장
- `aidlc-docs/inception/plans/unit-of-work-plan.md`로 저장
- 모든 [답변]: 사용자 입력용 태그 포함
- 계획이 시스템 분해의 모든 측면을 포괄하는지 확인

## 5단계: 사용자 입력 요청
- 사용자에게 [답변]을 작성하도록 요청: 계획 문서에서 태그를 직접 작성
- 분해 결정의 중요성 강조
- [답변] 작성에 대한 명확한 지침 제공: 태그

## 6단계: 답변 수집
- 사용자가 [답변]을 사용하여 모든 질문에 대한 답변을 제공할 때까지 기다립니다: 문서의 태그
- 모든 [답변]: 태그가 완료될 때까지 진행하지 마세요.
- 문서를 검토하여 [답변]이 없는지 확인하세요. 태그가 비어 있습니다.

## 7단계: 답변 분석(필수)
계속하기 전에 다음에 대한 모든 사용자 답변을 주의 깊게 검토해야 합니다.
- **모호하거나 모호한 응답**: "혼합", "어느 정도", "확실하지 않음", "의존적"
- **정의되지 않은 기준 또는 용어**: 명확한 정의가 없는 개념에 대한 언급
- **상충되는 답변**: 서로 상충되는 답변
- **세대 세부정보 누락**: 구체적인 지침이 부족한 답변
- **옵션을 결합한 답변**: 명확한 결정 규칙 없이 다양한 접근 방식을 병합하는 답변

## 8단계: 필수 후속 질문
7단계의 분석 결과 모호한 답변이 밝혀지면 다음을 수행해야 합니다.
- [답변]을 사용하여 계획 문서에 구체적인 후속 질문을 추가하세요. 태그
- 모든 모호성이 해결될 때까지 승인을 진행하지 마십시오.
- 필요한 후속 조치의 예:
  - "'A와 B의 혼합'을 언급하셨습니다. A와 B를 언제 사용할지 결정해야 하는 구체적인 기준은 무엇입니까?"
  - "'A와 B 사이'라고 말씀하셨는데요. 정확한 중간 접근 방식을 정의할 수 있나요?"
  - "'확실하지 않음'이라고 표시하셨습니다. 결정하는 데 도움이 되는 추가 정보는 무엇입니까?"
  - "'복잡성에 따라 다르다'고 말씀하셨는데요. 복잡성 수준을 어떻게 정의하시나요?"

## 9단계: 승인 요청
- 질문: "**작업 단위 계획이 완료되었습니다.aidlc-docs/inception/plans/unit-of-work-plan.md에서 계획을 검토하세요. 생성을 진행할 준비가 되셨나요?**"
- 사용자가 확인할 때까지 진행하지 마세요.

## 10단계: 로그 승인
- 타임스탬프와 함께 audit.md에 프롬프트 및 응답을 기록합니다.
- ISO 8601 타임스탬프 형식 사용
- 완전한 승인 메시지 텍스트 포함

## 11단계: 진행 상황 업데이트
- aidlc-state.md에서 단위 생성 파트 1(계획) 완료 표시
- '현재 상태' 섹션 업데이트
- 단위 세대 2부(세대)로의 전환 준비

# 2부: 세대

- [ ] 완료되지 않은 다음 단계 식별(첫 번째 [ ] 확인란)

- [ ] 계획에서 승인된 분해 접근 방식을 따릅니다.
- [ ] 계획에 명시된 기준과 경계를 사용하십시오.

## 14단계: 진행 상황 업데이트

## 15단계: 계속 또는 완료
- [ ] 더 많은 단계가 남아 있으면 12단계로 돌아갑니다.
- [ ] 모든 단계가 완료되면 장치가 설계 단계에 들어갈 준비가 되었는지 확인합니다.
- [ ] 단위 생성 단계를 완료로 표시

- 승인 상태를 명확하게 표시

## 19단계: 업데이트 진행 상황

## 중요한 규칙

### 계획 단계 규칙
- 상황에 맞는 질문만 생성
- 모든 질문에 [답변]: 태그 형식을 사용하세요.
- 진행하기 전에 모호성에 대한 모든 답변을 분석하십시오.
- 후속 질문으로 모든 모호함을 해결하세요
- 생성 전에 명시적인 사용자 승인 받기

### 생성 단계 규칙
- **하드코딩된 로직 없음**: 작업 계획 단위에 작성된 것만 실행합니다.
- **계획을 정확하게 따르세요**: 단계 순서에서 벗어나지 마세요.
- **체크박스 업데이트**: 각 단계를 완료한 후 즉시 [x]를 표시하세요.
- **승인된 접근 방식 사용**: Planning의 분해 방법론을 따릅니다.
- **완료 확인**: 진행하기 전에 모든 유닛 아티팩트가 완료되었는지 확인하세요.

- 계획에 대해 사용자 승인을 얻었습니다.
- [x]로 표시된 작업 단위 계획의 모든 단계
- 계획에 따라 생성된 모든 유닛 아티팩트:

  - 종속성 매트릭스가 있는 `unit-of-work-dependency.md`
