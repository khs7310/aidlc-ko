# 인프라 설계

## 전제조건
- 장치에 대한 기능적 디자인이 완료되어야 합니다.
- NFR 설계 권장(매핑할 논리적 구성 요소 제공)
- 실행 계획에는 인프라 설계 단계가 실행되어야 함을 나타내야 합니다.

## 개요
배포 환경에 대한 실제 인프라 선택에 논리적 소프트웨어 구성 요소를 매핑합니다.

## 실행 단계

### 1단계: 디자인 아티팩트 분석
- `aidlc-docs/construction/{unit-name}/functional-design/`에서 기능적 디자인 읽기
- `aidlc-docs/construction/{unit-name}/nfr-design/`에서 NFR 설계 읽기(존재하는 경우)
- 인프라가 필요한 논리적 구성 요소 식별

### 2단계: 인프라 설계 계획 수립
- 인프라 설계를 위한 확인란[]을 사용하여 계획 생성
- 실제 서비스(AWS, Azure, GCP, On-Premise) 매핑에 집중
- 각 단계에는 체크박스 []가 있어야 합니다.

### 3단계: 상황에 맞는 질문 생성
**지침**: 기능 및 NFR 설계를 철저하게 분석하여 설명을 통해 인프라 결정을 개선할 수 있는 모든 영역을 식별합니다. 포괄적인 인프라 적용 범위를 보장하려면 적극적으로 질문하십시오.

**중요**: 인프라 품질에 영향을 미칠 수 있는 모호하거나 세부 사항이 누락된 경우 기본적으로 질문을 합니다. 잘못된 인프라 가정을 하는 것보다 너무 많은 질문을 하는 것이 좋습니다.

**필수**: 각 카테고리에 대해 타겟 질문을 하여 다음 카테고리를 모두 평가하세요. 각 카테고리에 대해 기능 및 NFR 설계 아티팩트의 증거를 기반으로 적용 가능성을 결정합니다. 명시적인 정당성 없이 카테고리를 건너뛰지 마십시오.

- [답변]을 사용한 질문 삽입: 태그 형식
- 모호함, 누락된 정보 또는 설명이 필요한 영역에 중점을 둡니다.
- 사용자 입력이 인프라 결정을 향상시킬 수 있는 모든 곳에 질문을 생성하세요.
- **의심스러운 경우 질문하세요** - 과신은 잘못된 인프라 선택으로 이어집니다.

**평가할 질문 카테고리**(모든 카테고리 고려):
- **배포 환경** - 클라우드 공급자 기본 설정, 환경 설정 및 배포 대상에 대해 문의하세요.
- **컴퓨팅 인프라** - 컴퓨팅 서비스 선택, 크기 및 확장 요구 사항에 대해 문의하세요.
- **스토리지 인프라** - 데이터베이스 선택, 스토리지 패턴, 데이터 수명주기 요구 사항에 대해 문의하세요.
- **메시징 인프라** - 메시징/큐 서비스, 이벤트 기반 패턴 및 비동기 처리에 대해 문의하세요.
- **네트워킹 인프라** - 로드 밸런싱, API 게이트웨이 접근 방식 및 네트워크 토폴로지에 대해 문의하세요.
- **인프라 모니터링** - 관찰 도구, 알림 전략, 로깅 요구 사항에 대해 문의하세요.
- **공유 인프라** - 인프라 공유 전략, 멀티 테넌시, 리소스 격리에 대해 문의하세요.

### 4단계: 매장 계획
- `aidlc-docs/construction/plans/{unit-name}-infrastructure-design-plan.md`로 저장
- 모든 [답변]: 사용자 입력용 태그 포함

### 5단계: 답변 수집 및 분석
- 사용자가 모든 [답변]: 태그를 완료할 때까지 기다립니다.
- 모호하거나 모호한 답변 검토
- 필요한 경우 후속 질문을 추가하세요.

### 6단계: 인프라 설계 아티팩트 생성
- `aidlc-docs/construction/{unit-name}/infrastructure-design/infrastructure-design.md` 만들기
- `aidlc-docs/construction/{unit-name}/infrastructure-design/deployment-architecture.md` 만들기
- 공유 인프라인 경우: `aidlc-docs/construction/shared-infrastructure.md` 생성

### 7단계: 완료 메시지 표시
- 다음 구조에 완료 메시지가 표시됩니다.
     1. **완료 알림**(필수): 항상 다음으로 시작하세요.

```markdown
# 🏢 Infrastructure Design Complete - [unit-name]
```

     2. **AI 요약**(선택 사항): 인프라 설계에 대한 구조화된 주요 항목 요약을 제공합니다.
        - 형식: "인프라 설계가 [설명]:"으로 매핑되었습니다.
        - 주요 인프라 서비스 및 구성요소 나열(글머리 기호)
        - 배포 아키텍처 결정 및 근거 나열
        - 클라우드 제공업체 선택 및 서비스 매핑 언급
        - 워크플로 지침을 포함하지 마세요("검토해 주세요", "알려주세요", "다음 단계로 진행하세요", "진행하기 전에").
        - 사실에 기반하고 내용 중심을 유지하세요.
     3. **형식화된 워크플로 메시지**(필수): 항상 다음과 같은 정확한 형식으로 끝납니다.

```markdown
> **📋 <u>**REVIEW REQUIRED:**</u>**  
> Please examine the infrastructure design at: `aidlc-docs/construction/[unit-name]/infrastructure-design/`



> **🚀 <u>**WHAT'S NEXT?**</u>**
>
> **You may:**
>
> 🔧 **Request Changes** - Ask for modifications to the infrastructure design based on your review  
> ✅ **Continue to Next Stage** - Approve infrastructure design and proceed to **Code Generation**

---
```

### 8단계: 명시적인 승인을 기다립니다.
- 사용자가 인프라 설계를 명시적으로 승인할 때까지 진행하지 마세요.
- 승인은 명확하고 모호하지 않아야 합니다.
- 사용자가 변경을 요청하면 설계를 업데이트하고 승인 프로세스를 반복합니다.

### 9단계: 승인 및 업데이트 진행 상황 기록
- 타임스탬프가 포함된 audit.md의 로그 승인
- 타임스탬프와 함께 사용자의 승인 응답을 기록합니다.
- aidlc-state.md에서 인프라 설계 단계 완료 표시
