# NFR 디자인

## 전제조건
- NFR 요구 사항은 장치에 대해 완료되어야 합니다.
- NFR 요구 사항 아티팩트를 사용할 수 있어야 합니다.
- 실행 계획에는 NFR 설계 단계가 실행되어야 함을 나타내야 합니다.

## 개요
패턴과 논리적 구성 요소를 사용하여 NFR 요구 사항을 장치 설계에 통합합니다.

## 실행 단계

### 1단계: NFR 요구 사항 분석
- `aidlc-docs/construction/{unit-name}/nfr-requirements/`의 NFR 요구 사항을 읽어보세요.
- 확장성, 성능, 가용성, 보안 요구 사항 이해

### 2단계: NFR 설계 계획 수립
- NFR 설계를 위한 체크박스[]를 사용하여 계획 생성
- 디자인 패턴과 논리적 구성 요소에 중점을 둡니다.
- 각 단계에는 체크박스 []가 있어야 합니다.

### 3단계: 상황에 맞는 질문 생성
**지침**: NFR 요구 사항을 철저하게 분석하여 설명이 NFR 설계 품질을 향상시킬 수 있는 모든 영역을 식별합니다. 포괄적인 비기능적 설계 범위를 보장하려면 적극적으로 질문하십시오.

**중요**: NFR 설계 품질에 영향을 미칠 수 있는 모호함이나 누락된 세부 사항이 있는 경우 기본적으로 질문을 합니다. 비기능적 패턴에 대해 잘못된 가정을 하는 것보다 너무 많은 질문을 하는 것이 좋습니다.

**필수**: 각 카테고리에 대해 타겟 질문을 하여 다음 카테고리를 모두 평가하세요. 각 범주에 대해 NFR 요구 사항의 증거를 기반으로 적용 가능성을 결정합니다. 명시적인 정당성 없이 범주를 건너뛰지 마십시오.

- [답변]을 사용한 질문 삽입: 태그 형식
- 모호함, 누락된 정보 또는 설명이 필요한 영역에 중점을 둡니다.
- 사용자 입력이 패턴 및 구성 요소 결정을 향상시킬 수 있는 모든 곳에 질문을 생성하세요.
- **의심스러운 경우 질문하세요** - 과신은 기능적이지 않은 디자인으로 이어집니다.

**평가할 질문 카테고리**(모든 카테고리 고려):
- **복원력 패턴** - 내결함성 접근 방식, 재시도 전략 및 오류 복구 기대치에 대해 질문합니다.
- **확장성 패턴** - 확장 메커니즘, 로드 경계, 성장 예측에 대해 문의하세요.
- **성능 패턴** - 최적화 전략, 지연 시간 목표, 처리량 요구 사항에 대해 문의하세요.
- **보안 패턴** - 보안 구현 접근 방식, 위협 모델, 규정 준수 제약 사항에 대해 문의하세요.
- **논리적 구성요소** - 인프라 구성요소(큐, 캐시, 회로 차단기 등) 및 해당 통합 패턴에 대해 문의하세요.

### 4단계: 매장 계획
- `aidlc-docs/construction/plans/{unit-name}-nfr-design-plan.md`로 저장
- 모든 [답변]: 사용자 입력용 태그 포함

### 5단계: 답변 수집 및 분석
- 사용자가 모든 [답변]: 태그를 완료할 때까지 기다립니다.
- 모호하거나 모호한 답변 검토
- 필요한 경우 후속 질문을 추가하세요.

### 6단계: NFR 디자인 아티팩트 생성
- `aidlc-docs/construction/{unit-name}/nfr-design/nfr-design-patterns.md` 만들기
- `aidlc-docs/construction/{unit-name}/nfr-design/logical-components.md` 만들기

### 7단계: 완료 메시지 표시
- 다음 구조에 완료 메시지가 표시됩니다.
     1. **완료 알림**(필수): 항상 다음으로 시작하세요.

```markdown
# 🎨 NFR Design Complete - [unit-name]
```

     2. **AI 요약**(선택 사항): NFR 설계의 구조화된 주요 항목 요약 제공
        - 형식: "NFR 설계에 [설명]이 포함되었습니다:"
        - 구현된 주요 디자인 패턴 나열(글머리 기호)
        - 논리적 구성 요소 및 인프라 요소 나열
        - 복원력, 확장성 및 적용된 성능 패턴을 언급합니다.
        - 워크플로 지침을 포함하지 마세요("검토해 주세요", "알려주세요", "다음 단계로 진행하세요", "진행하기 전에").
        - 사실에 기반하고 내용 중심을 유지하세요.
     3. **형식화된 워크플로 메시지**(필수): 항상 다음과 같은 정확한 형식으로 끝납니다.

```markdown
> **📋 <u>**REVIEW REQUIRED:**</u>**  
> Please examine the NFR design at: `aidlc-docs/construction/[unit-name]/nfr-design/`



> **🚀 <u>**WHAT'S NEXT?**</u>**
>
> **You may:**
>
> 🔧 **Request Changes** - Ask for modifications to the NFR design based on your review  
> ✅ **Continue to Next Stage** - Approve NFR design and proceed to **[next-stage-name]**

---
```

### 8단계: 명시적인 승인을 기다립니다.
- 사용자가 NFR 설계를 명시적으로 승인할 때까지 진행하지 마세요.
- 승인은 명확하고 모호하지 않아야 합니다.
- 사용자가 변경을 요청하면 설계를 업데이트하고 승인 프로세스를 반복합니다.

### 9단계: 승인 및 업데이트 진행 상황 기록
- 타임스탬프가 포함된 audit.md의 로그 승인
- 타임스탬프와 함께 사용자의 승인 응답을 기록합니다.
- aidlc-state.md에서 NFR 설계 단계 완료 표시
