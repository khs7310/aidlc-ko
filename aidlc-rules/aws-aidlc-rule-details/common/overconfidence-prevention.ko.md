# 과신 예방 가이드

## 문제 설명

AI-DLC는 복잡한 프로젝트 의도 진술에 대해서도 명확한 질문을 충분히 하지 않음으로써 과신을 보였습니다. 이로 인해 적절한 요구 사항을 수집하는 대신 가정이 이루어졌습니다.

## 근본 원인 분석

과신 문제는 질문 건너뛰기를 장려하는 여러 단계의 지시문으로 인해 발생했습니다.

1. **기능적 디자인**: "해당되지 않는 경우 전체 카테고리 건너뛰기"
2. **사용자 스토리**: "카테고리를 필수 체크리스트가 아닌 영감으로 사용하세요"
3. **요구사항 분석**: 최소한의 질문을 유도하는 유사한 패턴
4. **NFR 요구 사항**: 철저한 분석을 방해하는 "만약" 조건

이러한 지시는 AI에게 포괄적인 요구 사항 수집을 장려하기보다는 질문을 피하라고 지시했습니다.

## 솔루션 구현

### 업데이트된 질문 생성 철학

**기존 접근 방식**: "꼭 필요한 경우에만 질문하세요."
**새로운 접근 방식**: "의심스러울 때는 질문을 해보세요. 과신은 좋지 않은 결과를 낳습니다."

### 주요 변경 사항

#### 1. 요구사항 분석 단계
- "필요한 경우에만"에서 "특별히 명확한 경우가 아니면 항상 질문 만들기"로 변경되었습니다.
- 종합 평가 영역 추가(기능적, 비기능적, 비즈니스 컨텍스트, 기술 컨텍스트)
- 적극적인 질문 접근 방식 강조

#### 2. 사용자 스토리 단계
- "전체 카테고리 건너뛰기" 지시문을 제거했습니다.
- 평가할 수 있는 포괄적인 질문 카테고리가 추가되었습니다.
- 향상된 답변 분석 요구 사항
- 강화된 후속 질문 의무

#### 3. 기능적 디자인 단계
- "만약" 조건을 포괄적인 평가로 대체했습니다.
- 더 많은 질문 카테고리 추가(데이터 흐름, 통합 포인트, 오류 처리)
- 모호성 감지 및 해결 요구 사항 강화

#### 4. NFR 요구사항 단계
- 기본 NFR을 넘어 확장된 질문 카테고리
- 안정성, 유지 관리성 및 유용성 고려 사항 추가
- 기술적 모호성에 대한 향상된 답변 분석

### 새로운 지침 원칙

1. **질문의 기본**: 모호한 부분이 있으면 명확한 질문을 하세요.
2. **포괄적 범위**: 모든 관련 카테고리를 평가하고 영역을 건너뛰지 마세요.
3. **철저한 분석**: 모든 사용자 응답의 모호성을 주의 깊게 분석합니다.
4. **필수 후속 조치**: 불분명한 답변에 대해 후속 질문을 만듭니다.
5. **모호함을 가지고 진행하지 마세요**: 모든 모호함이 해결될 때까지 진행하지 마세요

## 구현 지침

### 질문 생성의 경우
- 모든 질문 카테고리를 평가하고, 하나도 건너뛰지 마세요.
- 설명이 품질을 향상시킬 수 있는 곳에 질문하세요.
- 각 단계에 포괄적인 질문 카테고리를 포함합니다.
- 질문을 제외하는 대신 기본적으로 포함하도록 설정

### 답변 분석을 위해
- 모호한 응답을 찾으십시오: "의존적임", "아마도", "확실하지 않음", "혼합", "어딘가 사이"
- 정의되지 않은 용어 및 외부 개념에 대한 참조 감지
- 모순되거나 불완전한 답변 식별
- 모든 모호성에 대한 후속 질문 만들기

### 후속 질문의 경우
- 모호성이 감지되면 별도의 설명 파일을 생성합니다.
- 각각의 모호함을 해결하기 위해 구체적인 질문을 하세요.
- 모든 불분명한 답변이 명확해질 때까지 진행하지 마세요.
- 철저하게 - 과소설명하는 것보다 지나치게 명확하게 설명하는 것이 더 좋습니다

## 품질 보증

### 주의해야 할 위험 신호
- 복잡한 프로젝트도 묻지 않고 완료하는 스테이지
- 모호하거나 모호한 사용자 응답으로 진행
- 정당한 사유 없이 전체 질문 카테고리 건너뛰기
- 설명을 요구하기보다는 가정을 하세요.

### 성공 지표
- 프로젝트 복잡성에 대한 명확한 질문의 적절한 수
- 사용자 반응을 철저하게 분석하고 필요 시 후속 조치
- 구현을 진행하기 전에 명확하고 모호하지 않은 요구 사항
- 더 나은 사전 설명으로 인해 이후 단계에서 변경 필요성이 줄어듭니다.

## 유지

이 가이드는 다음과 같은 경우에 참조되어야 합니다.
- AI-DLC에 새로운 스테이지 추가
- 기존 단계 지침 업데이트
- 과신 문제에 대한 AI-DLC 성능 검토
- AI-DLC 질문 생성 원칙에 대한 팀원 교육

## 핵심 내용

**잘못된 가정을 하는 것보다 너무 많은 질문을 하는 것이 좋습니다.** 명확한 질문을 미리 묻는 데 드는 비용은 가정을 기반으로 잘못된 솔루션을 구현하는 데 드는 비용보다 훨씬 적습니다.
