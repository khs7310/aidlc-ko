# 적응형 깊이

**목적**: AI-DLC가 문제의 복잡성에 맞게 세부 수준을 조정하는 방법을 설명합니다.

## 핵심원리

**단계가 실행되면 정의된 모든 아티팩트가 생성됩니다. "깊이"는 문제의 복잡성에 맞춰 조정되는 해당 아티팩트 내의 세부사항 및 엄격함 수준을 나타냅니다.**

## 단계 선택과 세부 수준

### 스테이지 선택(바이너리)
- **워크플로 계획**에서 각 단계에 대해 실행 또는 건너뛰기를 결정합니다.
- **실행하는 경우**: 스테이지가 실행되고 정의된 모든 아티팩트를 생성합니다.
- **건너뛰는 경우**: 스테이지가 전혀 실행되지 않습니다.

### 상세 수준(가변)
- **간단한 문제**: 필수 세부정보가 포함된 간결한 아티팩트
- **복잡한 문제**: 광범위한 세부정보가 포함된 포괄적인 아티팩트
- **모델 결정**: 규범적 규칙이 아닌 문제 특성을 기반으로 함

## 세부 수준에 영향을 미치는 요소

모델은 적절한 세부 사항을 결정할 때 다음 요소를 고려합니다.

1. **명확성 요청**: 사용자의 요청이 얼마나 명확하고 완전합니까?
2. **문제 복잡성**: 솔루션 공간은 얼마나 복잡합니까?
3. **범위**: 단일 파일, 구성 요소, 여러 구성 요소 또는 시스템 전체?
4. **위험 수준**: 오류나 누락이 미치는 영향은 무엇입니까?
5. **사용 가능한 컨텍스트**: Greenfield와 Brownfield, 기존 문서
6. **사용자 선호도**: 사용자가 간결함이나 세부사항을 선호한다고 표현했습니까?

## 예: 요구사항 분석 아티팩트

**모든 시나리오는 동일한 아티팩트를 생성합니다**:
- `requirement-verification-questions.md`(필요한 경우)
- `requirements.md`

**참고**: 사용자의 초기 요청은 `audit.md`에 캡처됩니다(별도의 user-intent.md 필요 없음).

**세부 사항 수준은 복잡성에 따라 다릅니다**:

### 간단한 시나리오(버그 수정)
- **requirement-verification-questions.md**: 필요한 명확화 질문
- **requirements.md**: 간결한 기능 요구사항, 최소한의 섹션

### 복잡한 시나리오(시스템 마이그레이션)
- **requirement-verification-questions.md**: 여러 라운드, 10개 이상의 질문
- **requirements.md**: 포괄적인 기능 + 비기능 요구사항, 추적성, 허용 기준

**모든 시나리오는 동일한 아티팩트를 생성합니다**:
- `application-design.md`

**세부 사항 수준은 복잡성에 따라 다릅니다**:

### 단순 시나리오(단일 구성요소)
- **application-design.md**: 기본 구성 요소 설명, 주요 방법
- **comComponent-diagram.md**: 필수 관계가 포함된 간단한 다이어그램

### 복잡한 시나리오(다중 구성 요소 시스템)
- **application-design.md**: 세부 구성 요소 책임, 서명이 포함된 모든 방법, 디자인 패턴, 고려된 대안
- **comComponent-diagram.md**: 모든 관계, 데이터 흐름, 통합 지점이 포함된 포괄적인 다이어그램

## 모델의 기본 원리

**"더도 말고 덜도 말고 당면한 문제에 필요한 세부 사항을 정확하게 작성하세요."**

- 불필요한 세부사항으로 단순한 문제를 인위적으로 부풀리지 마십시오.
- 중요한 세부 사항을 생략하여 복잡한 문제를 간과하지 마십시오.
- 문제 특성이 세부 수준을 자연스럽게 유도하도록 하세요.
- 단계가 실행될 때 필요한 모든 아티팩트가 항상 생성됩니다.
